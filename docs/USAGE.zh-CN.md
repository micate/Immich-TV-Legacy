# Immich TV Legacy 使用指南

[返回项目首页](../README.md)

这是基于 [Immich Android TV](https://github.com/giejay/Immich-Android-TV) 的**非官方老电视兼容版**，用于浏览已有 Immich 服务器中的照片和视频。它不是 Immich 服务端，也不是手机照片备份客户端。

## 1. 使用前准备

- 一台 Android 6.0（API 23）或更高版本的电视/电视盒子，支持安装 APK。
- 已部署的 Immich 服务器，以及可以登录该服务器的账户。
- 电视能够访问服务器。建议先让电视、服务器和安装工具所在的电脑连接同一可信局域网，避免访客 Wi-Fi 的设备隔离。
- 实测环境：小米 MiTV4-ANSM0、Android 6.0.1、32 位 ARM、Immich Server 3.1.0。其他设备、服务端版本和视频编码尚不能保证兼容。

> Android 6 已是旧系统。本项目的兼容修复不等于系统安全更新。不要为了使用此应用将 ADB 端口或 Immich 服务器直接暴露到公网。

## 2. 获取 APK

**目前本仓库尚未发布预编译 APK。** 不要把上游的普通版 APK 当作 Legacy 兼容版：上游当前版本最低要求 Android 7。

- 发布后，可从本仓库的 [Releases 页面](https://github.com/micate/Immich-TV-Legacy/releases) 获取对应版本附件；只有存在 APK 附件时才可直接下载安装，`Source code` 压缩包不是安装包。
- 现在请按首页的[构建说明](../README.md#building-the-legacy-debug-apk)自行构建，或请可信的人协助构建。
- 当前版本构建产物：`app/build/outputs/apk/debug/ImmichTV-6.1.0-legacy.2.apk`。后续版本请使用实际生成的文件名。

请保留构建时使用的签名密钥。默认 debug 签名一般是电脑本地自动生成的，不同电脑的签名通常不同；无法直接覆盖安装对方签名的 APK。

## 3. 安装到电视

### 方法 A：U 盘或电视文件管理器

1. 将 APK 拷入 U 盘，连接电视并用文件管理器打开。
2. 如电视提示，允许该安装来源安装应用，再确认安装。
3. 从应用列表启动 **Immich TV Legacy**。

部分电视固件限制通过文件管理器安装 APK；此时可以尝试 ADB。无需为了安装应用关闭系统签名校验或刷机。

### 方法 B：网络 ADB（适用于支持此功能的电视）

1. 在电脑安装 Google 官方 [Android SDK Platform-Tools](https://developer.android.com/tools/releases/platform-tools)，解压后在该目录运行命令，或将目录加入 `PATH`。
2. 在电视设置中开启开发者模式，然后**单独开启 ADB 调试 / 网络调试 / USB 调试**，具体名称与路径取决于固件。仅开启开发者模式不够。
3. 在电视网络设置中查到电视的 IP。下面的地址都是示例，请替换为自己的地址：

```sh
# 192.168.1.50 是电视，不是 Immich 服务器。
adb connect 192.168.1.50:5555
adb devices -l
```

4. 电视出现调试授权窗口时，用遥控器选择“允许”。`adb devices -l` 显示 `device` 才表示授权完成。
5. 安装 APK：

```sh
adb -s 192.168.1.50:5555 install -r /path/to/ImmichTV-6.1.0-legacy.2.apk
```

看到 `Success` 后，从电视应用列表打开应用，也可以运行：

```sh
adb -s 192.168.1.50:5555 shell am start -n nl.giejay.android.tv.immich/.MainActivity
```

`5555` 是一些电视的传统网络 ADB 端口，不是所有型号都支持；使用无线调试配对的设备，请按电视显示的端口和配对流程操作。普通电视 USB-A 口通常是外设接口，连接电脑不一定能建立 ADB。

安装和排查完成后可执行 `adb disconnect 192.168.1.50:5555`，并在电视上关闭调试。**断开电脑连接不会自动关闭电视的调试服务。**

## 4. 创建电视专用 API Key

本客户端**不提供直接输入 Immich 账号密码的登录界面**。账号密码用于登录 Immich 网页，电视使用专用 API Key。

1. 在电脑或手机浏览器登录自己的 Immich 网页。
2. 打开账户设置中的 **API Keys / API 密钥**，创建一个专用密钥，例如 `Living Room TV`。入口名称可能随服务端版本变化。
3. 按所需功能授权。上游提供了[权限清单](../README.md#required-api-permissions)，其中包含照片、相册、时间线和人物等功能涉及的权限；这是上游清单，不代表本 fork 已逐项验证其最小权限集。请对照自己服务端提供的权限说明选择，不要直接授予全部管理员权限，也不要授予不需要的上传、删除或管理权限。
4. 安全保存密钥；有些界面只在创建时显示完整值。密钥丢失时可以撤销并重新创建。

**API Key 就是访问凭证。不要把它写入源码、提交到 GitHub、贴入 Issue 或截图中。** 如意外泄露，请在服务器撤销并重新创建。

## 5. 在电视登录

1. 启动应用，选择 **Sign in by API key**，然后选择 **Continue**。
2. 填写 **Server URL**，例如 `http://192.168.1.100:2283`：
   - 此处填写 **Immich 服务器**地址，不是电视 IP。
   - 保留 `http://` 或 `https://` 和实际端口。
   - 使用服务器根地址，不要追加 `/photos` 或 `/api`。
   - `localhost` 在电视上指电视本身，不能代表电脑上的服务器。
3. 将专用密钥填入 **API key**，注意不要多输入空格或换行。
4. 保持 **Disable SSL verification** 关闭。如果使用 HTTPS，应修复证书信任问题，而不是把关闭证书验证作为常规方案。
5. 选择 **Submit**，等待时间线或相册加载。

内网地址建议使用 API Key 登录。应用提示手机扫码登录需要可从互联网访问的服务器；没有必要为扫码而开放公网。

> HTTP 会在网络中明文传输凭证和媒体，只应在可信局域网中使用。具备合适证书和域名时优先使用 HTTPS。

## 6. 浏览照片与视频

- 用遥控器方向键移动焦点，确认键打开项目，返回键回到上一层。
- **Timeline**：时间线与回忆；**Albums**：相册；**Photos**：媒体列表（也可能包含视频）。
- **Random / People / Recent / Seasonal** 等入口按需使用，部分功能依赖服务器中的元数据和对应 API 权限。
- 视频无法播放时，优先检查服务器是否生成了电视可解码的转码版本。设置中的 **Force original video** 会强制使用原始视频；老电视通常应先保持该选项关闭。

已在实测设备上验证登录、时间线、全屏 PNG 显示、视频画面和回忆页面。尚未验证所有媒体格式、音频输出和屏保功能；进入页面不代表所有视频编码都可播放。

## 7. 更新与签名

本 fork 保留应用包名 `nl.giejay.android.tv.immich`，因此不能与同包名的上游版本作为两个独立应用同时安装。

- **同一签名**：用 `adb install -r` 覆盖更新，通常保留登录和设置。安装前仍建议记录服务器地址，并确保可以重新创建 API Key。
- **不同签名**：通常会出现 `INSTALL_FAILED_UPDATE_INCOMPATIBLE`。优先找到原签名密钥重新构建。若无法取得，只能在理解后果后手动卸载旧版，再安装新版本；**卸载会删除该应用在电视上的登录信息和设置**，但不会删除 Immich 服务器上的照片。
- 不要直接安装上游更新覆盖 Legacy；上游 APK 的最低系统要求和签名可能不同。
- 当前本地构建版本不提供自动更新保证，请自行查看仓库变更和 Releases。

## 8. 常见问题

| 问题 | 排查方法 |
| --- | --- |
| ADB 提示 `Connection refused` | 确认电视开机、IP 未变化、网络调试已开启；尝试关闭调试再开启。并非每台电视都开放 5555。 |
| ADB 显示 `unauthorized` | 在电视确认调试授权。若无提示，尝试撤销旧授权、重开调试并重新连接。 |
| ADB 显示 `offline` | 先断开再连接；必要时重启电脑上的 ADB 服务。 |
| `INSTALL_FAILED_OLDER_SDK` | 检查电视系统版本和 APK 来源；请使用 Legacy 构建而非上游普通版。 |
| `INSTALL_FAILED_UPDATE_INCOMPATIBLE` | 安装包签名不同，参见“更新与签名”，不要直接清空数据。 |
| 登录失败或没有照片 | 检查服务器地址、电视与服务器网络互通、API Key 有效性及权限；确认该账户本身能在网页看到媒体。 |
| 点击媒体即闪退，日志含 `Locale$Category` | 使用 `6.1.0-legacy.2` 或更高版本；该问题的修复也存在于先前本地测试包 `6.1.0-android6-local.2` 中。 |
| 视频黑屏、卡顿或没有声音 | 检查转码、网络、电视解码能力及音量设置；这类问题不一定是同一个崩溃原因。 |

## 9. 报告故障

请到本 fork 的 [Issues 页面](https://github.com/micate/Immich-TV-Legacy/issues)提交；如果仓库未启用 Issues，请先联系维护者。提供：

- 电视型号、Android 版本、CPU 架构（如果知道）。
- Legacy 客户端版本、Immich 服务端版本。
- 触发问题的操作步骤，以及照片还是视频、已知的格式或编码。
- 经过脱敏的相关崩溃日志。

例如将崩溃缓冲区保存到电脑：

```sh
adb -s 192.168.1.50:5555 logcat -b crash -d > immich-crash.txt
```

日志可能包含其他应用的旧崩溃。请按时间找到这次操作对应的 `nl.giejay.android.tv.immich` 记录，**删除密钥、请求头、私人地址、媒体文件名和个人信息后再分享**。不要上传整个未检查的日志、账户配置或私人相册截图。
